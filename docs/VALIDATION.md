# 2.3.0 로컬 검증 범위

최종 실행 파일을 빈 사용자 폴더와 개인 환경 변수를 제외한 환경에서 실행했습니다. 선택 자료인 `images.bin`을 제거한 상태에서도 실제 숨겨진 Qt 화면·SQLite·PNG 처리 47개 검사가 통과했습니다. 별도 검사에서는 배포한 실행 파일과 `images.bin`으로 합성 외형의 256×256 얼굴을 실제 렌더하고 양쪽 보관함의 자동 생성·표시를 확인했습니다.

```powershell
.\PriParaImageCamera.exe --offline-self-test report.json
.\PriParaImageCamera.exe --offline-portrait-self-test portrait-report.json
.\PriParaImageCamera.exe --offline-portrait-suite-test portrait-suite-report.json
.\PriParaImageCamera.exe --offline-conversion-self-test conversion-report.json
```

첫 명령은 `data.db`, 두 번째 명령은 `images.bin`과 시스템 Edge 또는 Chrome이 필요합니다. 두 명령 모두 임시 데이터와 합성 프로필을 사용합니다. 게임 프로세스·카메라·드라이버·실제 QR 통신에 접근하는 진입점은 검사에서 차단했습니다. 얼굴 검사에 사용하는 브라우저도 별도의 임시 프로필입니다.

세 번째 명령은 `data.db`와 `images.bin`을 사용해 실제 통합 창의 시작 경로를 검사합니다. 합성 마이티켓과 우정티켓을 미리 등록하고, 캐릭터 미리보기 버튼을 누르지 않은 상태에서 실제 얼굴 PNG가 자동 생성되어 양쪽 사용자 목록 아이콘으로 연결되는지 확인합니다. 별도의 렌더러 단독 검사와 구분합니다.

네 번째 명령은 공개용 합성 키·가상 프로필로 KR K21/K31 복호화·HK QR 생성·이미지 재독해·자동 보관·우정티켓→마이티켓 생성·취소·ID 정규화를 23개 항목으로 확인합니다. 실제 키가 없는 앱 시작과 필요한 자료 안내도 검사합니다. 별도 비공개 검사에서는 명시적으로 공급한 로컬 자료와 과거 KR 원문을 사용해 최종 EXE의 실제 변환을 확인했으며, 그 자료와 결과 티켓은 배포하지 않습니다.

추가 개발 검증에서는 메모·인쇄 시각·분류·휴지통, 캐릭터 생성, 즐겨찾기에서의 생성, 썸네일 갱신과 선택 유지, 저장 실패 시 종료를 확인했습니다. 앱 재연결은 합성 프로세스 상태와 시험 채널의 실제 Windows 메시지·공유 메모리로 검사했습니다. 늦은 복구 결과·실제 중지 신호·이전 QR 대기 명령이 재전송으로 이어지는 경우도 차단되는지 확인했습니다.

소스·카탈로그·이미지 메타데이터·실행 파일의 내장 코드와 문자열을 검토했습니다. 실행 파일의 앱 모듈 39개는 현재 소스와 일치했습니다. 공개 시작 QR과 게임/SDK/자산의 무결성 해시는 의도된 공개 자료로, 로컬 사용자 프로필·메모·통신 capability와 구분했습니다. 실제 복호화 키는 메모리 안에서만 비교해 공개 소스·실행 번들에 포함되지 않는지 확인했으며 검사표에 키 값을 기록하지 않았습니다.

이 결과는 격리 실행과 통신 구조 검증입니다. 업데이트한 프로그램의 실제 게임 로그인·티켓 수신과 재연결에 대한 사용자 플레이 확인은 별도로 필요합니다. 원격 저장소·과거 캐시·다른 사람의 복제본은 이 로컬 검토 범위에 포함되지 않습니다.
